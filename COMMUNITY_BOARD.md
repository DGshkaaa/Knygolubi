# Дошка спільноти та контакти читачів

Дошка `/board` замінює стару стрічку нових книг: вона призначена для запитів читачів, обміну та дарування особистих книг. Бібліотечний каталог залишається окремим.

## Сценарій

1. Схвалений читач публікує оголошення «Шукаю книгу», «Обміняю» або «Подарую», додає опис і за бажанням місце зустрічі.
2. Інший схвалений читач залишає приватний відгук. Автор отримує сповіщення з посиланням на оголошення.
3. Учасники продовжують приватну розмову на сторінці оголошення. Інші читачі та сторонні модератори не бачать повідомлень.
4. Після домовленості автор позначає оголошення завершеним. Нові відгуки закриваються, наявні розмови зберігаються.

Оголошення активне 30 днів, після цього приховується із загальної стрічки. У «Моїх оголошеннях» його можна поновити. Автор редагує або видаляє власні оголошення; модератори й адміністратори можуть видаляти неприйнятні публікації. Видалення прибирає також пов’язані розмови. Є ліміт 10 активних оголошень на читача і 50 повідомлень на розмову. Пошук працює за назвою, автором та описом, спеціальні символи трактуються буквально.

## Telegram у профілі

У редагуванні профілю є необов’язкове поле Telegram. Можна ввести `book_reader`, `@book_reader` або `https://t.me/book_reader`. Зберігається нормалізований нік. Сторонні URL, телефони й некоректні символи відхиляються. Підтримуються звичайні ніки довжиною 5–32 символи. Перевіряється формат, а не належність чи існування акаунта в Telegram.

Контакт видимий іншим схваленим читачам у профілі та відкривається через `https://t.me/...`. Порожнє поле видаляє контакт. Посилання з розмови веде до профілю співрозмовника. Email іншого читача через API профілю не повертається; у власному профілі адреса залишається.

## Розгортання

Потрібно розгорнути **і бекенд, і фронтенд** з одного коміту. Нових секретів або сторонніх сервісів не потрібно. Колекції `board_posts` і `board_threads` та індекси створюються автоматично під час роботи й запуску бекенду. Правило Render `/* → /index.html` з дією Rewrite має залишатися увімкненим для прямих переходів на сторінки дошки.

## Перевірки

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
cd frontend
npm run build
npm run lint
```

HTTP-тести перевіряють доступ, приватність розмов, редагування, видалення, строки дії, фільтри, ліміти, сповіщення та Telegram-контакти на ізольованих даних.

Для ручної перевірки з вигаданими даними можна запустити `python -m uvicorn tests.preview_board:app --host 127.0.0.1 --port 8000`, а фронтенд — на порту 5174. Тестові логіни описані в `tests/preview_board.py`. Цей допоміжний сервер запускається лише локально й не повинен використовуватися як production start command.
